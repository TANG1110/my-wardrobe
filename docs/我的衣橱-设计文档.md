## 1. 项目概述

《我的衣橱》是一款个人衣橱管理与穿搭搭配的 H5 应用，核心目标帮助用户"练习穿搭、看搭配是否适合自己"。用户将真实衣物存入衣橱，在一个根据自己性别和体型选择的人物形象上试穿搭配，通过 AI 生成真实上身效果，并记录每日实穿情况，让系统逐渐学习用户的穿搭偏好。

**核心闭环**：把衣服放进衣橱 → 选择人物（性别+体型）→ 选中衣物 → AI 虚拟试穿看真实上身效果 → 判断适不适合 → 出门打卡 → 系统学会你的偏好。

## 3. 系统架构

### 3.1 分层结构

```
数据层(data) → 业务Hook(hooks) → 页面(pages) → UI组件(components/ui)
```

单向依赖：页面不直接触碰 storage，所有持久化读写封装在业务 Hook 内部。

### 3.2 技术架构特征

- **单页多路由**：BrowserRouter，`/` 重定向到 `/wardrobe`，5 个一级/二级页面 + 404。
- **本地单机**：所有业务数据存浏览器 localStorage（scopedStorage 按 appId 隔离），不登录、不跨设备，打开即用。
- **AI 能力即服务**：抠图、虚拟试穿通过 capabilityClient 调用平台插件，不做前端图层合成。
- **页面间同步**：共享数据通过 localStorage 作为同步媒介，各页面独立 Hook 实例。

## 5. 核心功能设计与实现

### 5.1 AI 抠图（添加衣物页）

- **插件**：`clothing_image_background_matting_1`，actionKey=`imageMatting`
- **入参**：`{ clothing_image: [File] }`，SDK 自动上传转公网 URL
- **调用**：unary（非流式），`capabilityClient.load(pluginId).call('imageMatting', input)`
- **结果持久化**：取返回 `result.images[0]` → `imageToDataURL()`（fetch→blob→FileReader）转 base64 存入 localStorage，确保刷新不失效
- **失败降级**：catch 后标记失败 + toast + "重试"按钮，不落脏数据

### 5.2 AI 虚拟试穿（试穿页）

- **插件**：`virtual_try_on_image_generation_1`，actionKey=`imageToImage`
- **入参**：
  - `person_base_image`：人物底图 URL（来自性别+体型映射）
  - `clothing_reference_images`：衣物参考图 File 数组（`loadImageAsFile()` 将内网/base64 路径 fetch 转 File，SDK 自动传公网）
  - `clothing_description`：衣物文字描述 + 严格类别约束
  - `image_ratio: '3:4'`
- **防幻觉约束** `buildCategoryConstraint`：明确告知 AI"未选中的类别一律不得出现"，含光脚要求、配饰白名单、禁止擅自加配饰
- **两次降级重试**：①完整描述+全部参考图 → ②失败后简化描述+仅主衣物参考图 → ③再失败抛错提示
- **结果展示**：`BodyAvatar` 双图层，AI 生成图 onLoad 淡入覆盖底图，生成中 loading 遮罩

### 5.3 人物性别 + 体型选择

- **底图素材**：10 张静态人物剪影（aka.doubaocdn.com CDN）
  - 女性 6 档：standard / petite / curvy / plus-size / tall / slim
  - 男性 4 档：standard / tall / athletic / thin
- **数据结构**：每档有 `mappedParams`（bodyFat/shoulderWidth/legLength/waist 0-100），用于适合度评分规则匹配
- **联动**：选性别→自动重置 bodyType 为对应性别第一档并同步 mappedParams
- **兼容**：旧数据迁移（无 gender 默认女、无 bodyType 默认标准）

### 5.4 配饰多选

- 数据结构 `wornMap: Record<major, IClothing[]>`，每大类一个数组
- 单选类（上装/下装/外套/连衣裙/鞋靴）数组只存 1 件，再次点击**替换**
- 配饰类可存多件，再次点击同款**按 id 精确移除**
- 侧边栏按大类分组，配饰每件独立删除

### 5.5 衣物图层叠加说明

试穿页**不做前端图层叠加**——衣物"穿在身上"的效果完全由 AI 图生图生成（人物底图+衣物参考图+描述 prompt 一次性合成）。已选衣物在侧边栏仅作选择状态展示。

## 6. 核心数据模型

### 6.1 衣物 `IClothing`

```ts
{
  id: string;              // c_<timestamp>_<random6> 或 mock_<name>
  name: string;
  image: string;           // 抠图后 base64 dataURL
  category: { major: 'top'|'bottom'|'coat'|'dress'|'shoes'|'accessory';
              minor: string; fit: 'slim'|'regular'|'loose'; };
  params: { length: number; color: string; material: string; style: string; };
  createdAt: number;
  source: 'user' | 'mock';
}
```

### 6.2 搭配组合 `IOutfit`

```ts
{ id: string; name: string; items: string[]; createdAt: number; wearCount: number; }
```

### 6.3 每日打卡 `IDailyLog`

```ts
{ date: string; outfitId: string; clothesIds: string[]; createdAt: number; }
```

### 6.4 体型参数 `IBodyParams`

```ts
{ height: number; weight: number;
  gender: 'female'|'male'; bodyType: BodyType;
  bodyFat: number; shoulderWidth: number; legLength: number; waist: number; }
```

## 7. 数据存储（scopedStorage，localStorage）

| 存储键 | 数据结构 | 说明 |
|---|---|---|
| `wardrobe_clothes` | `IClothing[]` | 衣物列表（mock+用户混合） |
| `wardrobe_deleted_mock_ids` | `string[]` | 用户删除的 mock id，防重建 |
| `wardrobe_outfits` | `IOutfit[]` | 保存的搭配 |
| `wardrobe_daily_logs` | `IDailyLog[]` | 打卡记录 |
| `wardrobe_body_params` | `IBodyParams` | 人物体型 |

**Mock 完整性检查**（`useClothes` 核心）：启动时对比 22 件 mock 与本地+删除名单，缺失且未被删的自动补入（用户衣物排最前），全新用户直接注入全部 22 件。

**删除防重建**：删 mock 记录 id 到删除名单，下次不重建；用户上传衣物删除即永久。

## 9. 关键设计决策

| 决策 | 理由 |
|---|---|
| 不搞前端图层合成，用 AI 图生图做试穿 | 真实照片穿到插画人物上，前端叠加必然违和；AI 合成才有真实上身质感 |
| 用美术底图 + 档位选择替代参数化实时变形 | 程序化几何拼人没有美术感，换装游戏用固定美术资产+选模板 |
| 衣物参考图转 File 上传公网 | 内网/临时路径上游 AI 拉不到，必须转公网可访问 |
| 严格类别约束防幻觉 | AI 会擅自补鞋、加配饰，需显式负向约束 |
| localStorage + 完整性检查 | 本地单机应用，mock 用完整性检查避免版本号死锁 |

## 10. 已知限制与后续建议

- **数据不跨设备**：localStorage 本机存储，换设备/换浏览器不共享。
- **AI 试穿非即时**：每次生成有几秒等待，不能图层式瞬时切换。
- **AI 试穿质量依赖模型**：衣服形态、风格融合仍可能不完全精确。
- **已保存搭配"一键还原"未实现**：当前只支持保存，尚无载入/切换已存搭配的入口（建议补充）。
- **天气/场合推荐未做**：架构上留了扩展空间，可作为后续增强。
